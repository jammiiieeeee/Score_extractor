Phase 1: Frame Scanning (FrameStepper)

The program reads video frames sequentially, skipping ahead at configurable intervals to speed up scanning.

# src/application/extraction_components.py class FrameStepper: def __init__(self, video_service, config): # Calculate how many frames to skip between checks self.seek_step = max(1, int(config.frame_check_interval * fps)) def step(self): # Skip frames for speed if self.seek_step > 1: self.video.skip_frames(self.seek_step - 1) # Read next frame frame_img, timestamp, current_idx = self.video.read_next_frame() return Frame(frame_img, timestamp, current_idx)
Key Insight: We don't check every frame! With frame_check_interval=0.8, we skip ~24 frames on a 30fps video, making it 25x faster.
Phase 2: Page Change Detection (SSIM)

Uses Structural Similarity Index (SSIM) to detect when the top portion of the frame changes significantly.

# Compare TOP portion of frame (where page numbers appear) def _get_roi(self, img): h, w = img.shape[:2] y_end = int(h * self.config.top_analysis_ratio) # Top 34% roi = img[0:y_end, :] small = cv2.resize(roi, (320, ...)) return cv2.cvtColor(small, cv2.COLOR_BGR2GRAY) # SSIM: 1.0 = identical, 0.0 = completely different ssim_score = ssim( self._get_roi(self.last_stable_frame.image), self._get_roi(current_frame.image) ) # Trigger if below threshold (default: 0.96) if ssim_score < self.config.change_detection_threshold: # PAGE CHANGE DETECTED!

Why top 34%? Piano scores have page numbers at the top. When the page changes, the top changes first. The bottom (music notes) might look similar between pages.
Phase 3: A/B Frame Capture

Once a change is detected, we capture TWO frames with a time delay to get the clearest view.

def capture_a_b(self, trigger_frame): # A-frame: captured AFTER a small delay (0.3s) # This lets the page transition complete a_frame = trigger_frame delay_frames = int(self.config.a_capture_delay * self.fps) if delay_frames > 0: cap_idx = a_frame.index + delay_frames a_img, a_ts = self.video.read_frame_at(cap_idx) a_frame = Frame(a_img, a_ts, cap_idx) # B-frame: captured 3 seconds later (stability delay) # This ensures we have a clean, stable view b_idx = a_frame.index + self.stability_frames b_img, b_ts = self.video.read_frame_at(b_idx) b_frame = Frame(b_img, b_ts, b_idx) return a_frame, b_frame

Why two frames? Videos often have transitions, animations, or the playback bar moving. The A-frame catches the page change, the B-frame ensures stability.
Phase 4: Dynamic Bar Erase & Merge

The playback bar (progress indicator) moves across the screen. We detect it and merge A+B to remove it.

# Detect the playback bar by comparing A and B frames def merge_frames(self, frame_a, frame_b, ...): # Find where the bar is (column with maximum difference) diff = np.abs(a_top - b_top) col_sums = np.sum(diff, axis=0) bar_x = np.argmax(col_sums) # Overlay left portion of B onto A # This replaces the old bar position with clean content overlay_width = int(frame_b.shape[1] * overlay_width_ratio) merged = frame_a.copy() merged[:, :overlay_width] = frame_b[:, :overlay_width] return merged, bar_x, bar_width

Dynamic Bar Erase: The bar position changes every frame. By comparing A and B, we find exactly where the bar is and replace that region with clean content from the other frame.
Phase 5: Spike Guard Rails (Validation)

Before accepting a page, we validate the bar profile to ensure it's a legitimate page change.

# src/domain/deduplication.py def _get_bar_profile_peaks(self, frame_a, frame_b, crop_ratio): # Compute column-wise difference between A and B diff = np.abs(a_top - b_top) col_sums = np.sum(diff, axis=0) # Find peaks (spikes) in the difference profile peaks = [] for i in range(2, len(col_sums) - 2): if col_sums[i] > col_sums[i-1] and col_sums[i] >= col_sums[i+1]: peaks.append((i, col_sums[i])) return peaks # Guard Rail 1: Clean bar profile (2-4 peaks expected) def has_clean_bar_profile(self, frame_a, frame_b, crop_ratio): n = len(self._get_bar_profile_peaks(frame_a, frame_b, crop_ratio)) return 2 <= n <= 4 # Playbar has 2 edges + possible shadows # Guard Rail 2: Left spike within margin (left 20%) def has_left_spike_in_margin(self, frame_a, frame_b, crop_ratio): peaks = self._get_bar_profile_peaks(frame_a, frame_b, crop_ratio) if len(peaks) < 2: return False # Find leftmost spike position left_col = sorted(peaks[:2], key=lambda p: p[0])[0][0] margin_col = int(640 * self.config.bar_left_margin) # 20% of width return left_col < margin_col

Why Guard Rails?
  • Clean profile: Playbar creates 2 sharp edges (left/right). Too many peaks = noise
  • Left spike margin: Playbar always starts from left edge. If left spike is far right = false trigger
These prevent false positives from scene transitions, lighting changes, or camera movements.
Phase 5: Deduplication (3-Step Verification)

Before saving, we check if this page is a duplicate of an existing one.

def is_duplicate(self, frame_a, frame_b, b_number): # Step 0: OCR Force-Duplicate (fastest) if self.ocr_service.is_enabled(): num_a = self._get_cached_number(frame_a) num_b = self._get_cached_number(frame_b) if num_a == num_b: # Same page number = duplicate return True if num_a and num_b: # Different numbers = NOT duplicate return False # Step 1: Global Pixel Similarity (fast) sim_score = self._get_global_similarity(mask_a, mask_b) if sim_score > 0.995: # Nearly identical = duplicate return True if sim_score < 0.95: # Very different = NOT duplicate return False # Step 2: Row-wise Similarity (precise) return self._check_row_similarity(mask_a, mask_b)
Why 3 steps?
  • OCR: Fastest, most reliable (if page numbers visible)
  • Global similarity: Catches 95% of duplicates
  • Row similarity: Final check for borderline cases

Complete Flow Summary

1. Scan video frames (skip every 0.8s for speed)

2. Detect page change using SSIM on top 34%

3. Capture A-frame (0.3s delay) + B-frame (3s later)

4. Merge frames to erase playback bar

5. Guard Rails - Validate bar profile (2-4 peaks, left spike in margin)

6. Deduplicate using OCR → Global → Row checks

7. Save unique pages to disk

8. Generate PDF from collected pages
