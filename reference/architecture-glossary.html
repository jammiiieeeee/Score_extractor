Software Architecture Glossary

Key terms for understanding Clean Architecture

Abstraction
A simplified representation of something complex. In code, interfaces are abstractions that hide implementation details.
IVideoService is an abstraction - it says "what" a video service does, not "how"
Interface
A contract that defines methods a class must implement. Also called "Abstract Base Class" (ABC) in Python.
class IVideoService(ABC): defines open_video(), read_frames(), etc.
Dependency Injection (DI)
Passing dependencies (objects a class needs) into it, rather than having the class create them itself.
ExtractScoreUseCase receives IVideoService in __init__, doesn't create VideoService directly
Use Case
A specific business operation or workflow. Represents "what" the system does from a user's perspective.
ExtractScoreUseCase orchestrates the entire video-to-PDF workflow
Domain Model
Objects that represent core business concepts and rules. Pure data structures with behavior.
Frame class represents a video frame in our business context
Infrastructure
External services and libraries: databases, APIs, file systems, third-party code.
OpenCV (video), PaddleOCR (text recognition), ReportLab (PDF)
Separation of Concerns
Each part of the system has a single, well-defined responsibility.
Domain handles business rules, Infrastructure handles external integrations
Inversion of Control (IoC)
The framework calls your code, not the other way around. Dependencies are "inverted" - inner layers don't control outer layers.
Domain doesn't import Infrastructure; Infrastructure imports Domain interfaces
Mock
A fake object used in testing to simulate real dependencies.
MockVideoService provides test data without needing real video files
SOLID Principles
Five design principles for maintainable code. Clean Architecture implements all five:
  • Single Responsibility
  • Open/Closed
  • Liskov Substitution
  • Interface Segregation
  • Dependency Inversion
Tight Coupling
Classes directly dependent on concrete implementations, making changes difficult.
BAD: class MyVideo: import cv2 (hard dependency)
Loose Coupling
Classes depend on abstractions, allowing easy swapping of implementations.
GOOD: class MyVideo: def __init__(self, service: IVideoService)
