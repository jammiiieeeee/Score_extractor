## Design Specificity Verdict

**LLM assessment**: The palette is correct ebony-and-brass, but the concept stops at colors. Window has no title bar text (commented out). No spatial studio metaphors. Generic Unicode gear icon. No crafted surfaces, no material texture — reads as "minimal dark mode" not "precision instrument". The crop preview drag interaction is the single crafted moment, and it's only 240px tall.

**Deterministic scan**: 15 findings from detect.mjs — 3 categories of design-system drift:

1. **Font size 14px** (lines 90, 156, 268, 315) — 4 instances where `font-size: 14px` is used outside the DESIGN.md type ramp (which defines body=13px, label=12px, display=22px, mono=12px). These are tab labels and list items — they should use a documented size or DESIGN.md needs updating.

2. **Color #0d0d0d** (lines 138, 150, 184, 214, 227, 273, 365) — 7 instances. This IS documented in DESIGN.md as the input component's `backgroundColor`, but it's not listed in the `colors` top-level palette. The detector only checks the top-level palette, not component-specific colors. False positive — add `input-bg: "#0d0d0d"` to DESIGN.md colors.

3. **Color #b89230** (line 112) — pressed state for primary button. This is a darker brass variant not in the palette. Legitimate addition needed — either add `brass-dark: "#b89230"` to colors or use an existing brass variant.

4. **Radii outside scale** — `border-radius: 2px` (lines 197, 211) for slider groove/sub-page, `border-radius: 5px` (line 224) for progress bar fill chunk. These are sub-component radii that fall between the sm=4px and md=6px documented steps. Either add `xxs: "2px"` and a 5px step to the rounded scale, or adjust code.

False positives: #0d0d0d is a legitimate input/checkbox/combo background from the design system; it just needs to be lifted into the palette.

## Priority Issues

### P0 — Window has no title
**What**: `setWindowTitle` and `setApplicationName` are commented out (lines 1999, 2091). Taskbar shows "python.exe", window bar is blank.
**Why it matters**: Makes the app look abandoned. First impression for any user is an empty title bar.
**Fix**: `self.setWindowTitle("Score Extractor")` with a warm brass-themed suffix.
**Suggested command**: `/impeccable polish`

### P0 — ConfigTab is a wall of 17 spinboxes (Recognition #6: score 0)
**What**: Lines 770-900 — 17 parameters in a single flat grid with no sub-grouping, no categorization, no presets. "B-capture delay" sits next to "Pixel similarity threshold" with no headers or visual separation.
**Why it matters**: This is the single highest cognitive load violation. Users will feel stupid and abandon before extraction.
**Fix**: Add section headers (Detection, OCR, Bar Detection, Deduplication), collapse the advanced group by default, provide "Reset to defaults". Consider burying 12 of these under an "Advanced…" dialog.
**Suggested command**: `/impeccable distill` or `/impeccable layout`

### P1 — Crop ratio duplicated across both tabs
**What**: Crop ratio spinbox lives at line 771 in ConfigTab AND line 1283 in ExtractTab — same parameter, two locations, different context.
**Why it matters**: User changes in one tab, switches, sees a potentially different value. Confusing and undermines trust.
**Fix**: Remove from ConfigTab. Keep only on ExtractTab where the crop preview lives.
**Suggested command**: `/impeccable clarify`

### P1 — "Set as Default" is redundant
**What**: Line 1291 — button that suggests "saving" crop settings. But every spin change already calls `update_config` (line 1712). Auto-save is not communicated.
**Why it matters**: Creates anxiety that changes are lost unless clicked. Undermines confidence in the auto-save behavior.
**Fix**: Replace with a brief "✓ Auto-saved" indicator that fades after spin changes, or remove the button entirely.
**Suggested command**: `/impeccable clarify`

### P2 — Extraction auto-chains to PDF without user review
**What**: Lines 2060-2066 — after extraction completes, `on_completed` immediately calls `generate_pdf`. User cannot inspect extracted pages, remove bad captures, or reorder.
**Why it matters**: Removes user agency at the most critical decision point. A bad extraction produces a bad PDF silently.
**Fix**: Stop after extraction. Show page thumbnails. Let user review and approve before PDF generation.
**Suggested command**: `/impeccable shape`

### P2 — Tab inconsistency (Extract vs Config)
**What**: Tab 1 is labeled "Extract" (verb, imperative), tab 2 is labeled "Config" (noun, abbreviated).
**Why it matters**: Inconsistent labeling undermines the perception of craft. "Config" is not a noun users naturally reach for.
**Fix**: Tab 1: "Extract", Tab 2: "Settings" (noun, full word) or "Tuning" (studio metaphor).
**Suggested command**: `/impeccable clarify`

4. **Should extraction stop at "X pages captured — review & generate PDF"?** The current auto-chain robs the user of the chance to reject bad captures. Would a review step with page thumbnails increase confidence?
