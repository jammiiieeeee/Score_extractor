## Design Specificity Verdict
Generic with a piano veneer. Labels never mention sheet music, notation, page turn. The same layout could ship as "Slide Capture" unchanged.

## Overall Impression
Solid functional foundation wrapped in a genuinely nice dark theme — but UX falls apart mid-flow. First 30s feel guided, then hits wall of jargon, hidden parameters, shape-shifting button, and withholding progress information.

## Priority Issues
- [P1] Morphing action button is a reliability hazard
- [P1] Extraction phase is invisible
- [P1] Cross-thread calls on PreviewSeeker create data races
- [P1] _busy lock has no watchdog — permanent UI freeze if extraction hangs
- [P2] WCAG contrast failures across 6 widget types
- [P2] No page review before PDF generation
- [P2] YouTube download is uncancellable

## Persona Red Flags
- Jordan (first-timer): 6+ jargon terms, invisible progress, hidden critical settings, no onboarding
- Alex (power user): No accelerators, no batch/queue, no page-level review
- Sam (accessibility): Mouse-only critical interaction, state chameleon button

## Minor Observations
- "Set as Default" button is redundant with Config tab live-apply
- on_page_detected handler body is literally pass
- Log window 140px for 1-3 lines — 18% of vertical space
- Temp pixmap files never cleaned up
- Unused imports and dead style rules

## Questions to Consider
- What if Config tab's 17 spinboxes were replaced by a score type selector with 3 presets?
- What if action button were replaced by a visible 4-stage workflow?
- What if page count grew in real time during extraction?
