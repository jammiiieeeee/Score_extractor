## Overall Impression

The brass-and-ebony dark theme shows visual ambition, but the layout execution undermines it. `layout.setSpacing(0)` with ad-hoc `addSpacing(2/4/6)` is the single highest-impact issue — it flattens the layout hierarchy, makes sections bleed into each other, and prevents the video preview from becoming the focal point it should be. The same app's ConfigTab uses a clean `setSpacing(12)`, proving the codebase knows better. The video preview caps at 360px with `Policy.Fixed` — too small for precision crop work and unresizable.

## Priority Issues

### P0 — Zero-spacing layout destroys section hierarchy (line 1167)
**What**: `layout.setSpacing(0)` with manual addSpacing calls at only 4 of 12+ section boundaries. 8 boundaries have 0px gap.
**Why it matters**: Sections visually merge. The status label, crop preview, and seek bar have a 2px gap between preview→seekbar but 0px between project→status→preview. Users cannot quickly scan the 12-section column.
**Fix**: Replace with `layout.setSpacing(8)` and remove manual addSpacing calls. Use layout.insertSpacing between major logical groups.
**Suggested command**: `/impeccable layout`

### P0 — Video preview is fixed-height and unresizable (lines 1268–1270)
**What**: `setMinimumHeight(180)`, `setMaximumHeight(360)`, `setSizePolicy(Policy.Preferred, Policy.Fixed)`. The effective video area is height − 30px = 150–330px.
**Why it matters**: Piano scores demand visual scrutiny. At 150px min, staves, ties, ledger lines, and dynamics markings are hard to read. Users cannot enlarge the preview. Professional video tools allocate 50–60% of vertical space to preview.
**Fix**: Change to `Policy.Expanding` or `Policy.Preferred, Policy.Preferred`. Remove the 360px cap. Set min height to 240px.
**Suggested command**: `/impeccable layout`

### P1 — ExtractTab vs ConfigTab use incompatible spacing systems (line 1167 vs 749)
**What**: ExtractTab: `setSpacing(0)`. ConfigTab: `setSpacing(12)`. Same app, adjacent tabs, two spacing philosophies.
**Why it matters**: Users who switch between tabs experience a jarring density change. The inconsistency signals that layout was an afterthought rather than a designed system.
**Fix**: Unify both tabs under the same spacing constant.
**Suggested command**: `/impeccable layout`

### P1 — Status label visually orphaned with no spacing (lines 1260–1264)
**What**: The status label sits 0px from the project row above and 0px from the crop preview below. It reads as a caption for either adjacent element.
**Why it matters**: System status (Nielsen #1) requires clear visual separation to communicate meaning. A merged label undermines credibility.
**Fix**: Add 4px spacing on both sides.
**Suggested command**: `/impeccable layout`

### P2 — Progress bar flush against PDF row and log area (lines 1318–1328)
**What**: 0px between pdf_row → progress_bar → log_edit. During extraction, log text collides visually with the bar.
**Fix**: Add 6px spacing around progress bar.
**Suggested command**: `/impeccable layout`

### P2 — Seek bar groove height (24px) vs handle hit target (28px) mismatch (line 532 vs 192–194)
**What**: 24px minimum height groove with a 16px handle + 12px margin = 28px effective handle. Handle overflows groove by 2px.
**Fix**: Increase groove to 32px or reduce margin to −4px.
**Suggested command**: `/impeccable layout`

### P3 — Crop label in crop_row has no width constraint (line 1281 vs 1241)
**What**: project_label and pdf_label use fixedWidth(115). Crop label uses natural text width (~70px) — horizontal misalignment with the 115px column above.
**Fix**: Set crop_label fixedWidth to 115 or use a shared column alignment.
**Suggested command**: `/impeccable layout`
