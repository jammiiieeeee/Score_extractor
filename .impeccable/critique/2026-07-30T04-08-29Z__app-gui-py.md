## Design Specificity Verdict

**Grounded in product, but with a weak spot.** The "Master's Studio" concept is recognizably present — the tonal surface stack, brass accent discipline, and custom crop overlay with grip ridges all signal a bespoke instrument. The Config tab, however, visually collapses into a generic parameter grid that could belong to any dark-themed tool.

**Deterministic scan:** The Impeccable detector found 0 issues — expected, as it is designed for HTML/CSS and this is a PyQt6 desktop app. No browser visualization was possible.

---

## Overall Impression

The GUI has a strong conceptual foundation and genuinely thoughtful moments (the crop preview interaction, the tooltip quality, the state machine). But the design system isn't fully realized in code: the most visible CSS class selectors are broken, so secondary and danger buttons render as default brass instead of their intended styles. This is a P0 — the most-clicked action buttons are visually wrong. Fix that, and the entire interface tightens up considerably.

---

## What's Working

1. **CropPreviewWidget interaction** — The brass-tinted overlay band (40 alpha) with center grip ridges and `SizeVerCursor` on hover is a bespoke, tactile interaction that earns the "studio instrument" concept. This is the best piece of UI in the app.

2. **Config tooltip quality** — Every single parameter has a multi-line tooltip with safe range and rationale. This is rare and genuinely helpful. Users tuning extraction don't have to leave the app to understand what a parameter does.

3. **State machine clarity** — `_update_state()` evaluates exactly 5 boolean flags to produce 6 distinct UI configurations. Button visibility transitions (Start → Cancel → Open PDF) are well thought out.

## Priority Issues

### [P0] Secondary and Danger button styles are broken
- **What**: `QPushButton.secondary` and `QPushButton.danger` class selectors in the stylesheet are not matching because `setObjectName("secondary")` was used instead of `setProperty("class", "secondary")`. QSS treats `.secondary` as a class selector, not an object name selector. Every Browse…, Download, Re-extract, Cancel button renders as a default brass button.
- **Why it matters**: The visual hierarchy collapses — secondary actions look like primary actions. The design system's button vocabulary doesn't exist at runtime.
- **Fix**: Replace `setObjectName("secondary")` with `setProperty("class", "secondary")` and call `self.style().unpolish(btn); self.style().polish(btn)` on each affected button. Same for `"danger"`.
- **Affected lines**: `app_gui.py:1267, 1289, 953, 1396, 1414`
- **Suggested command**: `/impeccable polish app_gui.py`

### [P1] No keyboard shortcuts
- **What**: Zero keyboard accelerators. No Ctrl+O for open, no Ctrl+E for extract, no Esc to close modals.
- **Why it matters**: This is a precision tool used repeatedly. Alex (power user) will feel friction from session 2 onward.
- **Fix**: Add `QAction` shortcuts for common actions (Ctrl+O → browse, Ctrl+E → start extraction, Esc → cancel). Set tab order explicitly.
- **Suggested command**: `/impeccable optimize app_gui.py`

### [P1] Config tab — 16 parameters all visible at once, no collapsible groups
- **What**: All 16 spinboxes across 5 groups are expanded by default. `QGroupBox` doesn't support collapsible titles natively in Qt.
- **Why it matters**: A first-time user (Jordan) sees a wall of knobs. Working memory is overloaded — they must mentally track 16 values across 5 groups.
- **Fix**: Implement collapsible group boxes with a custom clickable title toggle, or show the most common 1-2 groups expanded and collapse the rest.
- **Suggested command**: `/impeccable layout app_gui.py`

### [P2] Token drift — `WOOD` color defined in code, absent from DESIGN.md
- **What**: `WOOD = "#6d4c2a"` is defined in the palette at `app_gui.py:48` but has no counterpart in the DESIGN.md color spec. Similarly, `QFormLayout` `font-size: 14px` at `app_gui.py:315` is undocumented.
- **Why it matters**: The design system isn't the source of truth — the code has drifted. Future changes may misuse or lose the WOOD color.
- **Fix**: Add WOOD to DESIGN.md as a note for potential future use, or remove it from the palette if unused. Sync the documented spec.
- **Suggested command**: `/impeccable document app_gui.py`

### [P2] Settings button uses emoji `⚙` (U+2699)
- **What**: `"⚙ Settings"` at `app_gui.py:1362` uses a Unicode gear emoji.
- **Why it matters**: The design system explicitly forbids "gradient text, glass effects, or sparklines" and relies on Segoe UI for all typography. An emoji breaks the visual language — it renders differently across fonts and OS versions, and reads as unpolished.
- **Fix**: Replace with a simple text label "Settings" with no icon, or generate a monochrome SVG gear icon that matches the brass aesthetic.
- **Suggested command**: `/impeccable polish app_gui.py`

## Persona Red Flags

**Alex (Power User):** No keyboard shortcuts. No recent files list. No Ctrl+Enter to start extraction. Tab order is widget-creation default, not logical flow. Alex will complete the primary action in ~45 seconds via mouse, but by the 10th extraction the repetition will feel grating.

**Jordan (First-Timer):** Land on Extract tab — clear enough. But "Start-time capture" checkbox meaning is ambiguous without reading the tooltip. Clicking Settings reveals 16 parameters with no collapse affordance. The Cancel button renders as a primary brass button due to the P0 CSS bug, making it look as important as Start Extraction. Confusion risk.

**Riley (Stress Tester):** The 5-minute watchdog timer has zero user-visible indicator — extraction could appear hung for 4:59 before anything happens. No frame-processing rate or ETA is shown. Riley will cancel prematurely, not knowing the watchdog is there.

## Questions to Consider

1. **Why does the Config tab look like a hospital monitor rather than a mixing desk?** If the concept is "The Master's Studio," what would make adjusting extraction parameters feel like turning knobs on a Neve console rather than filling out a spreadsheet?

2. **The crop preview could show live page detections during extraction.** Instead of just a progress bar and scrolling log text, cycling detected pages through the preview widget would give the user both progress visibility and quality confidence in real time.

3. **The single most-clicked button (`⚙ Settings`) uses an emoji while the crop preview has a custom painted overlay with grip ridges.** What makes Settings worth less design attention than the preview, and what would it take to give it the same level of craft?
